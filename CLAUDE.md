# CLAUDE.md — Instructions for AI developers

1. **Read `OpenDrive-Bridge-Whitepaper.md` in full before writing any code.** It is the single source of truth for scope, architecture, phases (P0–P6), and quality gates. Appendix D lists non-negotiable rules.
2. Follow the phase order in whitepaper §5. Do not skip exit criteria. Current phase: **P3, transfer pipeline** — P0, P1 and P2 are complete, and within P3 the upload pipeline (`upload.go`) and the error classification layer (`classify.go`) have landed. Next: download pipeline, then `internal/jobs`.
   - New bindings follow the folder module's pattern: a service struct, one method per endpoint with the verb and session placement in its doc comment, a row in the module contract test (`folder_contract_test.go` shows the shape), and a recorded fixture in `testdata/fixtures/` for anything whose response shape came off the wire.
   - **Probe the live API before writing a binding.** Six of the discrepancies so far (D26, D28, D30, D31 among them) were spec-versus-reality gaps that mock tests happily passed. Every boolean parameter in particular must be settled on the wire: `file/move_copy` takes only the strings `"true"`/`"false"`, `file_edit_online` only an integer, and `folder/move_copy`'s documented boolean `false` is refused outright.
   - Existence checks use the parent listing or `idbypath`, never `folder/info.json` (D27). Files differ: `file/info.json` does report a removed file as gone.
   - **Never leave an upstream artefact behind.** A record `create_file` made and did not fill is invisible to the user, and enough of them in one folder make upstream refuse further writes there (D39). `Upload` reclaims its own record unless told to keep it; integration tests must clean up every artefact, intermediate ones included.
   - Credentials go through `opendrive.CredentialStore` only; `internal/keystore.Open` chooses the backend and is the "no persistence = configuration error" gate. `MemoryTokenStore` is test-only and reports itself ephemeral. Never introduce another path that stores a password.
   - All three platforms now have a native vault: macOS Keychain and Linux Secret Service through their CLIs (secret on stdin, never in process arguments), Windows through the Credential Manager API (`credman_windows.go`, no cgo). The encrypted file is only for environments with no vault at all, and on Windows its ACL is tightened with `icacls` because NTFS ignores the POSIX mode bits. Each backend is tested against the real vault on its own CI runner.
3. **`docs/error-taxonomy.md` and `pkg/opendrive/classify.go` are the sole authority on what an upstream failure means and whether it may be retried.** Upstream's status codes and messages routinely describe something other than what went wrong — an HTML 401 that has nothing to do with the token (D38), and a 403 whose "permission" wording is byte-identical for a transient condition and for a real denial (D39, D40). Classification takes evidence (status + body shape + Content-Type + endpoint identity, plus a rate-limited access probe where the response is not decisive); it never takes upstream's word. Consequences that are not negotiable: a non-JSON body can never yield a credential kind; nothing ambiguous or non-API-shaped may drive the auth state machine; `APIError.Temporary()`/`RetryAfter()` are the only retry authority, and no binding, pipeline or job may re-derive them. A new disguise gets a section in the taxonomy and a rule in `classify.go` — never a patch at the call site.
4. Upstream behavior: trust the live Swagger specs (`https://dev.opendrive.com/api/v1/resources/*.json`) and real sandbox responses over the PDF. Record discrepancies in `docs/discrepancies.md` — there are 40 so far, and several show the PDF is simply wrong (D12, D14, D15). Run the live suite with `scripts/integration-test.sh` (build tag `integration`; the account now has full write rights, and D26 is the kind of bug only it catches). Refresh the spec archive with `scripts/fetch-spec.sh`, which reads the test credentials from the OS keychain; it must run authenticated, since anonymously the explorer exposes only 21 of 220 operations.
5. Every gotcha in whitepaper §2.6 (14 items) must have at least one test case.
6. Never log passwords/tokens; token redaction in logs is mandatory (§9.4). Persisting credentials is allowed **only** through the CredentialStore (`internal/keystore`: OS keyring or explicitly configured encrypted file) per whitepaper v1.1 §2.2/§9.2 — never in config files, plain files, env dumps, or process args.
7. `docs/` holds official OpenDrive reference material (the PDF and the spec archive) — read-only, never modify. `docs/discrepancies.md` and `docs/error-taxonomy.md` are ours and are kept current.
8. Conventional Commits; every PR includes tests; keep `main` releasable.
9. Coverage gates: `pkg/opendrive` ≥ 85%, `internal/*` ≥ 75% (§6.3).
